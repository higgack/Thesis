# Thesis Model Application Review

**Problem**: Minimize token usage and API costs while maintaining evaluation accuracy.

**Three Levers**:

1. **Lever 1 — Minimum Code**: No speculative params, no single-caller abstractions. Walk the ladder (needs to exist? → stdlib → native → dependency → one line → min block). Never cut input validation, auth, error handling.

2. **Lever 2 — Say Less**: Drop wind-up, hedging, narration. Answer first, explain why/non-obvious only. Fragment over paragraph.

3. **Lever 3 — Agent-to-Agent Compress**: When reader is another agent → minified JSON (columnar). Never pretty-print to programs. Use stable keys, not position.

**Apply reflexively** — don't spend reasoning tokens on the skill itself.

---

## Key Rules

- Code under 100 lines per file when possible.
- JSON between agents: `{"c":["metric","value"],"r":[["accuracy",0.95]]}` over full objects.
- Document non-obvious tradeoffs only; code speaks for itself.
- Keep tests runnable; leave one assertion per function.
- Deployment: full commit -> push -> PR -> merge -> verify chain; see DEPLOY.md.
